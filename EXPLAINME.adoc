= Ddraig — EXPLAINME

The receipts for README.adoc: where each claim is implemented, what it does
not cover, and the status of every proof obligation, for anyone who wants to
check rather than trust.

== Claim-to-implementation map

=== Site configuration

[quote, README.adoc]
____
an optional `ddraig.toml` (title, base URL, language, description, author,
menus, `[extra]` values) and `data/*.toml` files for templates. Front matter
overrides site values. Checked by a *total* decision before anything is
written; every mistake is reported with its line and column.
____

How this is implemented::
`link:Toml.idr[]` parses TOML into located tables; `link:Config.idr[]`
(`%default total`) decides validity in `validateConfig`, returning every
problem as a located `Diagnostic` (`link:Diagnostic.idr[]`). The build stops
before writing when there is any problem (`Ddraig.idr`, `failBuild`).

Caveat::
The TOML parser is `covering`, not total, and reads a documented subset of
TOML (link:CONFIGURATION.adoc[]); anything else is reported, not guessed.

=== Proof-carrying accessibility (O3)

[quote, README.adoc]
____
every page is run through a *total* decision (`Attest.idr`) for the
machine-decidable content-tree criteria: exactly one `<h1>`, non-skipping
headings, and alt text on every image (an image without alt is a located
build error, `DDR0801`, unless marked `{.decorative}`).
____

How this is implemented::
`link:Attest.idr[]` defines the three predicates as decidable propositions
and `certify` returns either the violations or an `Attested` value whose
erased `echo` field proves `output = renderDoc source.blocks` for a source
carrying the (erased) accessibility witness. The Markdown parser
(`Ddraig.idr`, `inlineNodes`) produces `UnlabelledImg` for an image with no
alt and no `{.decorative}` marker, so the omission is represented rather than
guessed; `missingAltDiags` locates it for `DDR0801`.

Caveat::
Raw HTML blocks are passed through and not inspected; the attestation file
records how many each page has. Template-owned criteria (page `lang`,
`<main>`, contrast, the template's headings) are not covered yet. See the
<<proof-ledger>> and link:docs/proof-debt.adoc[].

=== Typed HTML core

[quote, README.adoc]
____
a typed, correct-by-construction HTML core whose `render` is *total* and in
which an informative image node cannot be constructed without non-blank alt
text
____

How this is implemented::
`link:Html.idr[]` (`%default total`): `render`, `renderForest` and
`renderDoc` are structurally recursive. `MkAlt` requires an erased
`So (trim text /= "")`, and `mkAlt` is the total boundary check for alt text
from untrusted input.

Caveat::
Tag and attribute names are arbitrary strings: they are escaped but not
validated as HTML names, and `Raw` content is emitted verbatim. Well-formedness
is about the structure the constructors produce.

=== Accessible default theme

[quote, README.adoc]
____
the default theme is *WCAG 2.2 AAA-capable*: contrast- verified ≥ 7:1 palette
(light + dark)
____

How this is implemented::
The stylesheet is `defaultStyle` in `link:Ddraig.idr[]`; the measured ratios
are recorded in link:ACCESSIBILITY-CHECKLIST.adoc[].

Caveat::
The ratios were computed by hand and are not re-checked by CI, so the ledger
records this as `argued`.

== Known gaps

[CAUTION]
====
Whole-page accessibility: README's O3 claim covers the content tree only. The
template's `lang`, `<main>` landmark and its own headings are not certified
until the typed template (work package 1, milestone 2). Listed as `open` in
the <<proof-ledger>>.
====

[CAUTION]
====
Raw HTML passthrough is outside the certificate. It is counted, not inspected.
====

[CAUTION]
====
The "WCAG 2.2 AAA-capable" palette's contrast ratios are hand-computed, not
re-checked by CI.
====

== Proof Ledger

Checker for every `proven` row: Idris 2 0.8.0 (commit `6ca00e72`, in the
digest-pinned `ghcr.io/stefan-hoeck/idris2-pack` image used by `ci.yml`),
`idris2 --check <file>`, with no extra flags; each module is
`%default total`, with no `believe_me`, `assert_total` or `partial`.
The `trusted-base` CI job checks for escape hatches.
